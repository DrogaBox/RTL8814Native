# AWDL peer presence: event 47, ioctl 415 and the PPP waiting queue

How the kernel signals the presence and absence of an AWDL peer, what it does with the packets
received from a peer before `wifip2pd` publishes it, and what the RTL8814 driver has to implement
so those packets reach the stack. Closes open point #17 of
[AWDL_INDICE.md](AWDL_INDICE.md) §8.2. It also corrects step 5 of the RX recipe of
[AWDL_DATA_ENCAP.md](AWDL_DATA_ENCAP.md) §7. Base: KC 25G241 (macOS 26.7.1) in IDA and `wifip2pd`
of the same build. Anything unchecked carries `?`.

## 1. Event 47 (`APPLE80211_M_PEER_PRESENCE`): absence only

It is emitted by two sites, both with `postMessageSync(0x2F, buf, 0x44)` over the manager
interface (`awdl0`). The search for `mov esi, 2Fh` before each `postMessageSync` call finds no
more:

| Emitter | Call | Context |
|---|---|---|
| `IO80211PeerManager::removePeer` `0xffffff8002254096` | `0xffffff8002254248` | just before, logs `"%s postPeerAbsence for %02X:…"` |
| `IO80211AWDLPeerManager::cleanUpForPeerRemovedFromNDP` `0xffffff8002214cf2` | `0xffffff8002214d6d` | followed by `pppDone(false)` at `0xffffff8002214d77` |

68 B payload, zeroed except:

| Offset | Size | Value |
|---|---|---|
| `+0x00` | 6 | MAC of the peer (`peer+88..93` of the common ivars) |
| `+0x08` | u32 | `1` |

The `u32@8 = 1` means **absence**: it is the only value the kernel writes and the accompanying log
is `postPeerAbsence`. The daemon discards the event if that field is not 1
([AWDL_ETAPAS_2_A_4.md](AWDL_ETAPAS_2_A_4.md), event table). In the daemon the struct is named
`apple80211_peer_presence_indication` (string `0x10045cfe0`).

**Presence** does not arrive via event 47. The kernel has no emitter of 47 with another value:
the arrival of a peer is seen in the action frames (event 48), and the daemon handles it in its
neighbor table (`WiFiInterface.NeighborDiscoveryTable`, log `"Posted peer presence for %s on %s"`
in `sub_1002823D0`).

## 2. Ioctl 415 (`APPLE80211_IOC_POST_PRESENCE_DONE`): the daemon releases the packets

`setPOST_PRESENCE_DONE` (`0xffffff800228d968`) calls at `0xffffff800228d9b9`
`IO80211AWDLPeerManager::setAwdlPostPeerPresenceDone` (`0xffffff800221c978`):

```
peer = findPeer(req + 4)                       // apple80211_awdl_ppp_done: u32 version, MAC @4
if (safeMetaCast(peer, IO80211AWDLPeer)) IO80211AWDLPeer::pppDone(peer, true)
return 0
```

`IO80211AWDLPeer::pppDone(bool)` (`0xffffff80021bfb08`) stores the bool in flag `+1758` of the
AWDL ivars of the peer (`this+0x20`):

- **`true`** (from the 415): drains the PPP queue in batches of 64 with `dequeuePPPWaitPacketFromHead`
  and delivers each batch with slot **+0xF30** of interface `awdl0` (`sendPendingPacketsToStack`).
  Logs `"Posted Peer Presence for …, uploading %d packets to stack"`.
- **`false`**: delivers nothing. Logs `"Posted Peer Absence for …"`. Callers are
  `IO80211AWDLPeerManager::removePeer` (`0xffffff800221721c`, after `flushPacketsWaitingForPPP` at
  `0xffffff80022177e4`, call at `0xffffff80022177ee`) and `cleanUpForPeerRemovedFromNDP`.

The 415 is generated by `wifip2pd`. The binary has exactly two `0x19F` immediates, and both are
in functions logging `"Post peer presence for %s"`:

| Function | Send | Payload |
|---|---|---|
| `sub_1000CA0F0` (no direct calls: protocol method) | `0x1000ca412` → `sub_1000CABE0(415, …)` | `apple80211_awdl_ppp_done` with the peer MAC |
| `sub_1000D6000` (via thunk `sub_1000CA0C0`, from the witness table `0x100517bf8`) | `0x1000d6229` → `sub_10004A490(415, …)`, only if byte `+32` of the object is 1 | `{u32 version = 1, peer MAC}` |

The struct `apple80211_awdl_ppp_done` is 12 B ([AWDL_STRUCTS.md](AWDL_STRUCTS.md)). The neighbor
table calls that publish method (`sub_1002823D0`, log `"Posted peer presence for %s on
%s"`). Several Swift paths reach it (`sub_10028F280`, `sub_100305990`,
`sub_10040B650`, `sub_10041C470`). Which peer event triggers each path is not traced `?`.

## 3. The PPP waiting queue (*post peer presence*)

RX path of a data packet of `awdl0`:

1. **`IO80211VirtualInterface::inputPacket`** (`0xffffff8002333cac`, slot **+0xB50**). For role
   6 it looks up the peer by the SA (`ether_header+6`). If there is no peer, it drops and adds
   `incrementNumInputPacketsDropped`. Multicasts `33:33:00:00:…`, `33:33:80:00:00:FB` and
   `01:00:5E:00:…` have their own peer and manager checks, and are dropped if they do not pass
   them. The rest goes to
2. `IO80211PeerManager::skywalkInputPacket` (`0xffffff800225d554`), which calls slot +0x168 of
   the peer:
3. **`IO80211AWDLPeer::skywalkInputPacket`** (`0xffffff80021bf9a4`). If flag `+1758` is 0
   (no 415 yet for that peer), it calls `peerDiscoveredOnBothSide` and enqueues the packet with
   `enqueuePPPWaitPacketAtTail` (`0xffffff80021bf9fa`). Then it sets `*consumed = 1` and returns 1.

The queue is a list at `+1760` (head) and `+1768` (tail) of the AWDL ivars of the peer. Each entry
is a descriptor of `allocZeroAwdlPacketDescriptor` with the packet at `+8` and the
`mach_absolute_time` at `+16`. There are three exits:

| Exit | Function | Interface slot |
|---|---|---|
| 415 received | `pppDone(true)` | +0xF30 `sendPendingPacketsToStack(pkts, n)` |
| Packet with over 2000 ms in queue | `ageoutPacketsWaitingForPPP` (`0xffffff80021aa7ca`), from `monitorPeer` (`0xffffff80021a9294`, call at `0xffffff80021a9711`) | +0xF38 `freePendingPackets(pkts, n)` |
| Peer removed | `flushPacketsWaitingForPPP` (`0xffffff80021bfe44`) | +0xF38 |

## 4. What the family leaves to the driver

In the base class the two slots only log an error:

| Slot | `IO80211VirtualInterface` | `AppleBCMWLANProximityInterface` |
|---|---|---|
| +0xB50 `inputPacket` | implemented (§3) | inherits the family one |
| +0xF30 `sendPendingPacketsToStack` | `0xffffff8002334e68`: only `IOLog("… Not Implemented")` | `0xffffff800172a716` |
| +0xF38 `freePendingPackets` | `0xffffff8002334e88`: only `IOLog("… Not Implemented")` | `0xffffff800172a812` |

Broadcom uses the `RxCompletionQueue` of the interface (`ivars+1016`):

- `sendPendingPacketsToStack`: `stagePacket(pkt, false, false)` (slot +0x340) for each packet,
  then `requestEnqueue(0, 0)` (slot +0x298) and, if it returns something other than 0,
  `flushPackets` (slot
  +0x330).
- `freePendingPackets`: `freePendingPackets(pkts, n)` of the queue (slot +0x348).
- Without the queue, it logs `"FAIL : Invalid Rx Completion Queue available"`.

Queue implementation per class (cells read from each vtable):

| Cell | `AppleBCMWLANPCIeSkywalkRxCompletionQueue` | `AppleBCMWLANSkywalkRxCompletionQueue` |
|---|---|---|
| +0x298 | `requestEnqueue` (`0xffffff8001546d18`) | `IOSkywalkRxCompletionQueue::requestEnqueue` (`0xffffff8002b2d6d8`), inherited |
| +0x330 | `flushPackets` (`0xffffff80015466fe`) | `flushPackets` (`0xffffff80015d83a2`) |
| +0x340 | `stagePacket` (`0xffffff8001546cc8`) | `stagePacket` (`0xffffff80015d805e`) |
| +0x348 | `freePendingPackets` (`0xffffff8001546852`) | `freePendingPackets` (`0xffffff80015d8328`): only log `"Not Implemented"` |

The PCIe queue `freePendingPackets` walks the array, skips the null entries, clears bit
`0x80` of a private Broadcom byte (`*(pkt+0x78)+0x90`) and returns each packet to the pool with
`IOSkywalkPacketBufferPool::deallocatePacket` (pointer `0xffffff80017fa328` →
`0xffffff8002b2c0de`; pool at `*(*(queue+0x140)+0x18)`, call at `0xffffff800154689d`). For
`awdl0` of the RTL8814 the equivalent is returning each packet of the array to its RX pool with
`deallocatePacket`, a symbol that `Source/AirLayer/AWDLInterface.cpp` already imports.

`IO80211AWDLPeerManager` has its own `sendPendingPacketsToStack` (`0xffffff80022389e6`) and
`freePendingPackets` (`0xffffff8002238c40`), which only forward to the +0xF30/+0xF38 cells of the
interface (`*(ivars+1376)`); they have no code xrefs.

Consequences for the `awdl0` interface of the RTL8814:

1. **Call `inputPacket`** (+0xB50) with every RX packet before delivering it, like Broadcom at
   `0xffffff800154a65c` ([AWDL_DATA_ENCAP.md](AWDL_DATA_ENCAP.md) §5). Return 0: drop.
   `consumed = 1`: the packet belongs to the family and is not touched. Any other value: deliver
   it to the queue. Enqueueing without passing through `inputPacket` skips the peer filter, the
   PPP retention and the peer accounting.
2. **Override +0xF30 and +0xF38.** If the interface inherits those of `IO80211VirtualInterface`,
   the retained packets never reach the stack. Moreover they are not freed, because the base
   versions do nothing with the array `?` (pool leak). With the project's own RX queue:
   `stagePacket` + `requestEnqueue`, or `enqueuePackets` per batch as the STA layer does, at
   +0xF30; return to the pool at +0xF38.
3. Both slots are called by the `PeerManager` from its context (`monitorPeer`, ioctl 415),
   not from the driver RX thread. The lock with which they are entered is not checked `?`.

## 5. When the kernel considers the peer routable

`IO80211AWDLPeer::setPeerRoutable` (`0xffffff80021aad6c`; called by `monitorPeerRssi`,
`shouldStopAFProcessing` and `peerDiscoveredOnBothSide`) is the one that logs
`postPeerPresence`. It sets `+120 = 1` in the AWDL ivars and stores the timestamp at `+200` of the
common ones. Before that it requires:

- **Peer seen on 5 GHz or with sufficient RSSI.** If `isDualBandPeerDiscoveredOn5GHz` is false,
  the peer RSSI (`+1188`, or `+1180 − 10`; −100 if both are 0) must be greater than or equal to
  the threshold at `PM+10276`. If not, it logs `"Not Routable … outside bubble"`. The values are
  set by `determineAndSetEdgeRssiThreshold` (§5.1).
- **End of the posting guard** (`waitForPostingPeer` `0xffffff80021b801c`). If
  `PM+65193` bit 0 or `+1756` of the peer are active, it waits `ndpPostingGuardTimemSec`
  (`PM+65216`;
  128 ms if it is 0) from the first AF (`+736`), unless `+1757` is active.
- **`LLAValid` and `AWDLOn`.** If either is missing, it logs
  `"Cannot post peer presence … (LLAValid %d AWDLOn %d)"`. Per the log argument order:
  - `LLAValid` is `PM+65308` bit 0. Writers: `initParamsToDefaults` (`0xffffff80021c818f`),
    `interfaceStateChange` (1 at `0xffffff80021d9b39`, 0 at `0xffffff80021d9b44`) and
    `monitorAWDLState` (`0xffffff80021ed932`). Which interface state activates it is not traced
    `?`.
  - `AWDLOn` is `PM+16096` bit 1. `reportDataPathEvents` logs that same bit as `isAwdlOn`.

### 5.1 RSSI thresholds

`IO80211AWDLPeerManager::determineAndSetEdgeRssiThreshold(uint)` (`0xffffff80021e0f5e`, writes
at `0xffffff80021e0fc1`–`0xffffff80021e1107`) chooses between two sets:

| Field | Normal | Extended |
|---|---:|---:|
| `PM+10268` (firmware edge; AF drop at `actionFrameProcessInput`) | −70 | −78 |
| `PM+10272` (host edge) | −65 | −78 |
| `PM+10276` (routable only on 2.4 GHz) | −45 | −58 |

The extended set is used if the argument (number of AirPlay services) is not 0, if `PM+16156` bit 0
is active or if `increaseRssiThresholdForSingleStreamDevice` requests it. When the edge changes,
the kernel sends the firmware value to the driver with **ioctl 135**
(`APPLE80211_IOC_AWDL_ELECTION_RSSI_THRESHOLDS`, `apple80211RouteInternal(0x802869C8, 135, …)`).
It is a 20 B buffer with zeros in the first 16 bytes and the threshold at `+16`.

For the RTL8814 the first condition matters: with the radio fixed on a 5 GHz channel the peer is
seen on 5 GHz and the 2.4 GHz threshold does not apply. If the radio stays on channel 6, the peer
has to arrive with −45 dBm or better (−58 in the extended set) to become routable.
