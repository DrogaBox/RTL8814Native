# The low latency companion interface (llw0): what it requires, what its absence breaks and the full path in the kernel

It closes the pending question in `AWDL_WIFIP2PD_POST_CREATE.md` (§2.1 row 5, §2.4) and `AWDL_STRUCTS.md` (§3.4): who orders the creation of the companion interface `llw0` (internal role 4 of `wifip2pd`, `COMPANION_SKYWALK_IF_CREATE` type 293), what happens if the request fails or the interface never appears, and what the full kernel chain is from the apple80211 dispatch to `AppleBCMWLANLowLatencyInterface`. Base: `wifip2pd.x86_64` (md5 `a120cfccfa2783303604ce5be9e1763a`) and `BootKernelExtensions.kc` (md5 `f489ff8be80e6013a1bf47561dcaef45`), analysis with IDA 9.4 headless (Hex-Rays + disassembly) over copies of the IDBs in `Build/ida_awdl/task_awdl_llw/` (`a*_probe*.py`/`a*_out.txt`, `k*_probe*.py`/`k*_out.txt`). Addresses are VAs of the indicated binary; anything unverified goes as `?`.

## Result

**The kext of a stage 1 (wifip2pd accepts `awdl0` without peers) may not implement type 293: `awdl0` gets created and accepted all the same.** The 293 request is only emitted when creating the internal-role-4 companion, always after `awdl0` exists and has a handle; if it fails, `wifip2pd` logs two errors and continues (the init of `AWDLInterface` swallows the error by design, `sub_100416D00`), without destroying `awdl0`, without marking AWDL as degraded and without retrying at boot. The only operational consequence is the absence of `llw0` (low latency datapath and its statistics). Detail and exact code in §5.

## 1. wifip2pd part — emission of type 293

### 1.1 The emitter `sub_10004B300` (0x10004b300, 0x5ce bytes)

- It builds the `apple80211req`: ifname @+0 copied with `strlcpy(buf, chars, 16)` (`sub_100063940`) from the name property of the parent object via keypath `unk_10045FE08`; type **293** @+16 (`LODWORD(v66) = 293`); length **24** @+24; data @+32 = 24 B buffer `{u32 code = a5, u32 op = 1, remaining 16 B}` (`v61[0] = a5`, `v61[1] = 1`). It calls `Apple80211RawSet` at **0x10004b3e6** on the parent object's `InterfaceHandle` (`InterfaceHandle_reference`).
- `a5` (the payload's `code`) arrives from the caller: in the disassembled range 0x100047c30–0x100048061 r8 is not rewritten, so at the call it holds the fifth input argument of the per-role creator. Its exact value on the AWDL path was not determined (`?`; the kernel does not consult it, see §3.2) — it matches the `?` already noted in `AWDL_STRUCTS.md` §3.4.
- Success path: returned name read with `String.init(cString:)` from **payload+8** (`v62`); if not empty, `getifaddrs`/`AF_LINK` poll with callback `sub_10004B960` (via `sub_100046B00`); then, depending on the parent handle's role: role 1 → `if_nametoindex("llw0")` with the packed literal `813132908` = `0x30776C6C` at **0x10004b814**; role 2 → `if_nametoindex("llw1")` (`829910124` = `0x31776C6C`) at **0x10004b862**. It returns the verified name or nil.
- Error paths (both throw a Swift error and return nil):
  - Missing parent (`object == nil`): log `"Failed to create low latency interface because parent %s was not found"` (string `0x100494ca0`, site 0x10004b639), error code `-4031` (`0xFFFFF0C1`), **without sending the RawSet**.
  - `Apple80211RawSet` ≠ 0: log `"Failed to create low latency interface for %s because %@"` (string `0x100494cf0`, site 0x10004b50f); the error code is the value returned by the RawSet.

### 1.2 Only caller and sending condition

`sub_10004B300` has **exactly one code xref**: `0x100048061` (`sub_100047660+0xa01`). The per-role creator `sub_100047660` (0x100047660, 0x22ca bytes) dispatches by the internal role code:

- Branch table `dword_10004992C` (12 entries of 32 B with signed offset, referenced with `lea` at 0x100047c02): case 0 → selector `mov edi,0x6E65` ("en") at 0x100047c52; case 1 → `mov edi,0x6C647761` ("awdl") at 0x100047c99; case 2 → "nan" (0x100047c77); case 3 → "ir" (0x100047c88, meaning unconfirmed `?`); **case 4 → `mov edi,0x776C6C` ("llw") at 0x100047C70**.
- After the selector, the expected name is built with `String.append` of the prefix (0x100047cb0) plus the decimal description of a counter (0x100047cf0, thunk of `CustomStringConvertible.description`), and a loop (0x100047d47–0x100047d7f) polls against the handle map `self+64` (`sub_100026600` at 0x100047d33) until finding the first unit without a handle.
- The handle of the **parent** is resolved against the same dictionary `self+64` before the dispatch, looking up the parent's name (arguments a3/a4) — that is what the pseudocode of `sub_100047660` shows (`v52 = sub_100026600(v76, v81)`, result in `[rbp+object]`); the disassembly only makes one of the lookups visible (the poll by the constructed name at 0x100047d33), so the parent lookup stays in the non-disassembled range 0x100047660–0x100047c30 (`?` exact placement).
- Final dispatch `jpt_100047E85` (0x100047e85): the **case 4 jumps to 0x10004803f**, which loads the parent (`mov rdi,[rbp+object]`), the name (rsi/rdx) and calls `sub_10004B300` at **0x100048061** with the Swift error register (r12) at zero (0x10004805e).

That is: **type 293 is only sent when creating an internal-role-4 (LowLatency) interface against an already existing parent.** No feature gate appears in the chain: the preference flags `lowLatencyRequired` (`0x1004473b0`, in `sub_10007CBE0`/`sub_10007D3E0`/`sub_1001021D0`) and `isLowLatencyOn` (`0x1004d3a8a`/`0x1004dd6d1`) have no xrefs from `sub_100047660`, `sub_10041B1F0` nor `sub_100416D00`.

### 1.3 Trigger chain (always after the creation of awdl0)

1. `sub_10036C2B0` — detects the absence of the AWDL interface and writes `"No AWDL interface found. Creating AWDL interface"` (string `0x1004a1350`).
2. `sub_1003654A0` (creation task) → `sub_10040F300` at **0x100365850** → init of `AWDLInterface` `sub_100416D00` at **0x10040f331**.
3. `sub_100416D00` → creation of the companion `sub_10041B1F0` at **0x100417e19**.
4. `sub_10041B1F0` (0x10041b1f0, 0x598 bytes): if the companion ivar is already populated → `"Ignoring request to create AWDL companion low latency interface since it is already present: %s"` (string `0x1004a7a00`, site 0x10041b3d6) and returns the existing one; if not → `"Creating companion low latency interface"` (string `0x1004a36b0`, site **0x10041b48b**) and invokes **by witness** the creation method of `CoreP2P.AppleDevice` with the literal **4** in the first argument (between 0x10041b48b and 0x10041b62f).
5. The `AppleDevice` method is the thunk `sub_10004D300` (0x10004d300: `return sub_100047660(*self, a2, a3, a4, a5 & 0xFFFFFFFFFFFF)`), present in the class's method table at 0x100548668 (neighbor of `sub_100042A50`, `sub_10004D1E0`–`sub_10004D2C0`); its invocation is dynamic, with no code callers (`?` exact ObjC/witness path). The alternative witness paths ending in `sub_100047660` are `sub_100207060`/`sub_100207160` (calls at 0x1002070bb/0x1002071b7, referenced from the tables 0x100517b80 and 0x10052cb38).
6. On success, `sub_10041B1F0` builds the `CoreP2P.WiFiInterface` object with `sub_10027EDA0` (call at **0x10041b62f**) and returns it; `sub_100416D00` saves it in the ivar `companionLowLatencyInterface` (offset read from the field descriptor, `*(class+672)`; the ivar name in the field metadata `0x1004a9e80`).

The creation of the companion is therefore **unconditional within the construction of `AWDLInterface`**, and that construction happens in the task that creates `awdl0`: when case 4 runs, the parent has already gone through the full cycle of `VIRTUAL_IF_CREATE` (94), IORegistry wait and handle (role 1). The NAN equivalent (`sub_1003AC420`, called from `sub_1003324C0+0x1e85`, `sub_100338480+0x3eb6` and `sub_1003B3F10+0x1bf9`) replicates the same pattern with the logs `"Failed to create NAN companion low latency interface"` (`0x1004a3670`), `"Creating companion low latency interface"` (`0x1004a36b0`, site 0x1003ac6cb) and `"Ignoring request to create NAN companion low latency interface since it is already present: %s"` (`0x1004a36e0`).

## 2. wifip2pd part — what happens if the 293 fails or llw0 never appears

### 2.1 Request failure (fast path, no waits)

- `sub_10004B300` throws the RawSet error (log `0x100494cf0`).
- The error epilogue of case 4 (**0x100048DE1**) writes `"Failed to create interface %s on %s with error %@"` (string `aFailedToCreate_1`, `__os_log_impl` site at **0x100048fb5**); the role name of the `%s` comes from the switch `jpt_100048EB8` (case 0 "AWDL" `0x4C445741` at 0x100048eba, case 1 "NAN" `0x4E414E` at 0x100048f1d, cases 2/3 "Low Latency" — bytes `4C 6F 77 20 4C 61 74` + `65 6E 63 79` at 0x100048f0d–0x100048f16).
- Then it removes its "creation in progress" entry from the per-role semaphore dictionary (`sub_100027A70` at 0x100049089, release `sub_100063E50` at 0x1000490a8) and **signals the semaphore in a loop until draining it** (`OS_dispatch_semaphore.signal()` at 0x1000490C0, repeated while it returns ≠ 0) so as not to hang waiters, and returns nil (0x1000490E4: `r14=0`, `rbx=0`).
- **There is no retry** on this path and **there is no awdl0 teardown mechanism**: the binary has exactly two `Apple80211RawSet` sites (0x100048d95 type 94 and 0x10004b3e6 type 293) and none of type 95 (`VIRTUAL_IF_DELETE`), already closed in `AWDL_WIFIP2PD_INTERFACE_LIFECYCLE.md` §5 and re-verified here.

### 2.2 Success without a verifiable interface (slow path, 30 s at most)

If the 293 answers success but the returned name does not verify (the `"llw0"` literal that `sub_10004B300` returns when `if_nametoindex` succeeds leaves the second word of the `String` at 0, and if the kernel created nothing the name comes back empty or nil), case 4 enters the companion-specific wait:

- `DispatchTime.now()` + **30 s** (`mov qword [r12], 0x1E` at **0x100048AA6**) and `OS_dispatch_semaphore.wait(timeout:)` at **0x100048B13** on the role 4 semaphore of dictionary `self+176` — the same one the IORegistry discoverer signals when seeing an interface with role `LowLatency` (code 4 match in `sub_100043720`, direct signal at **0x100045297** without creating a handle; see `AWDL_WIFIP2PD_POST_CREATE.md` §1.2).
- Timeout → `"Timed out while waiting for the low latency interface with parent %s"` (string `0x1004939a0`, site **0x100048beb**) → cleanup of the in-progress entry and nil. Signal → continues at 0x1000492A9 (re-queries the in-progress entry of role 4 with `sub_100026970` at 0x1000492e0).
- The "in progress" wait for concurrent creators (same role 4) uses the other loop with 30 s (`mov qword [r12], 0x1E` at 0x10004913b, `wait(timeout:)` at 0x1000491a8) and its timeout writes the generic `"Timed out while waiting for interface %s"` (string `0x100493910`, site 0x10004974b) with the interpolated role name ("AWDL"/"NAN"/"NAN Data" at 0x100049701/0x100049263/0x100049712).

Practical conclusion: a kext that **rejects** the 293 produces an immediate failure; one that **accepts and creates nothing** produces a wait of up to 30 s per attempt and then the same logical failure. In both cases `awdl0` is untouched.

### 2.3 The error is absorbed in the init and in the recovery

- `sub_100416D00` (init of `AWDLInterface`): after the call to `sub_10041B1F0` (0x100417e19), if there is an error it retains it, writes `"Failed to create the companion low latency interface for AWDL: %@"` (string `0x1004a75c0`, site **0x100417ead**, with `bridgeErrorToNSError`) and **continues the init**: next it registers for power state changes (`"Registering for Power State changes from wifid"`, `sub_10038EA80`, blocks with `sub_100443D40`), calls `sub_10041B7F0`, `sub_100393DB0`/`sub_1003945E0` and completes the construction. The companion ivar is only written when there was no error; the `AWDLInterface` object is returned all the same.
- Later recovery: `sub_1004184D0` (recovery method of the low latency interface of `AWDLInterface`, 0x1004184d0 + queues up to ≈0x100419a2a) re-invokes `sub_10041B1F0` (queued site **0x10041993c**); if it fails it writes `"Failed to recover the low latency interface %s: %@"` (string `0x1004a7b70`, site **0x100419a2a**) and continues with the companion at nil. Its callers: `sub_1004182B0` (0x100418384), `sub_100428460` (0x100428775) and `sub_1004287A0` (0x100428ab5) — recovery/monitoring paths of the `AWDLInterface`.
- Nothing marks AWDL as "unhealthy" because of the companion's absence: all static consumers read it from an Optional and log the failure (besides §2.3, `"Failed to recover the low latency interface %s"` in `sub_1003B3F10+0x1ca0`, string `0x1004a3ed0`, and the statistics `"Attempting to submit low latency statistics for %s"`, string `0x1004a40b0` at 0x1003b611c). The consumption of the optional fields in those large paths was not verified instruction by instruction (`?`), but no observed path destroys or disables `awdl0`.

### 3.5 The two companion pointers and what goes after to llw0

- There are **two links**, both written at creation: (1) the pointer the Broadcom code uses, at **ivars+120 of Proximity** (out-param of `createSkywalkInterface`; read by the "already exists" check of 0xffffff8001722ef2 and by `flushFlowQueues`, `0xffffff800172ac9e`, which with a null companion calls only the base — **null-safe**, no panic risk from absence); (2) the IO80211 family link, written by `IO80211VirtualInterface::setCompanionLowLatencySkywalkInterface` (**0xffffff8002334c6e**) called from `withProvider`, which saves the pointer at **ivars of `IO80211VirtualInterface` +216** (getter `getCompanionLowLatencySkywalkInterface`, `0xffffff80023344cc`).
- **`wifip2pd` does not open an Apple80211 channel toward llw0**: the discoverer treats code 4 by signaling the semaphore without creating a handle (0x100045297), so there is no `RawGet`/`RawSet`/event monitoring of the daemon over `llw0` via Apple80211 (static xref verification; `?` for witness uses of the companion `CoreP2P.WiFiInterface` object, e.g. the `'i'` ioctls 130/131 of `sub_100058420`/`sub_1000586D0` (resolved in `AWDL_STAGE4_LLW_CLOSURE.md` §2: IPv6 socket, not apple80211), whose interface-name comes from an unresolved keypath `unk_10045FE58`/`unk_10045FE78`).

## 4. Verdict for stage 1

The `wifip2pd` code that decides everything:

1. **Single, conditioned emission**: `Apple80211RawSet` type 293 only in `sub_10004B300` (0x10004b3e6), with only caller the case 4 of the per-role creator (`0x100048061` in `sub_100047660`, dispatch `jpt_100047E85` → 0x10004803f). It is sent against the handle of the **parent** (`awdl0`), already created and accepted: the trigger chain goes through the AWDL creation task (`sub_1003654A0` → 0x100365850) and the init of `AWDLInterface` (`0x10040f331` → `sub_100416D00` → `sub_10041B1F0` at 0x100417e19), without feature gate.
2. **The failure does not contaminate awdl0**: RawSet error → log `0x100494cf0` in `sub_10004B300` + log `0x100048fb5` in epilogue 0x100048DE1 → signal to waiters (0x1000490C0) → nil; the init absorbs it with the log `0x1004a75c0` (0x100417ead) and **continues**; no `RawSet` 95 nor any teardown path of `awdl0` exists; no retry except the explicit recovery (`sub_1004184D0`), which also swallows the failure (`0x100419a2a`).
3. **No permanent blocking**: if the kext returns an error, the flow fails on the spot; the llw-specific 30 s wait (0x100048A90–0x100048B13, timeout log 0x100048beb) only runs when the request "succeeds" without a verifiable name, and it is capped.
4. Therefore, a stage-1 kext can (a) not implement type 293 (the modern dispatch returns 102 if the table entry is empty, see `AWDL_STRUCTS.md` §4) or (b) implement it returning an error: in both cases `awdl0` stays created, published in IORegistry with `IO80211VirtualInterfaceRole = AirLink` and accepted by the discoverer and by `wifip2pd`. Option (c) — answering success without creating anything — works but costs 30 s per attempt and contributes nothing. If the real companion is ever wanted, the kernel contract is closed in §3.2-§3.3: create a custom Skywalk interface with a role publishing `IO80211InterfaceRole = "LowLatency"`, BSD prefix `llw`, write the name at payload+8 and guarantee that `if_nametoindex` resolves it.
