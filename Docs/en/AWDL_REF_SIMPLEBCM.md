# SimpleBCM as a reference: AirPortBrcmNIC on Sequoia/Tahoe without the system's IOSkywalkFamily

Review of the open project SimpleBCM (github.com/laobamac/SimpleBCM, clone at
`~/re_cache/work/ref_simplebcm`, commit `624fca1`, 2026-10-31). Code reading only;
nothing from the repository is compiled, loaded or run. The paths `ref_simplebcm/…` are relative to
that
clone. Verification status: everything cited with `ref_simplebcm/…:line` was read directly in the
code; what depends on binaries the repository does not carry (the Apple kexts) is marked `?`.

## 1. What it is

A Lilu plugin (kext `cn.laobamac.SimpleBCM`, personalities over `IOResources`,
`ref_simplebcm/SimpleBCM/Info.plist:21-41`) plus a set of kexts injected by OpenCore.
A single SimpleBCM.kext binary serves Sequoia (Darwin 24) and Tahoe (Darwin 25)
(`ref_simplebcm/README.en.md:48`); the ABI selection happens at runtime via
`getKernelVersion()`. The goal is that Apple's AirPortBrcmNIC (Broadcom PCI) works on
Sequoia/Tahoe with the native Wi-Fi API (Wi-Fi menu, CoreWLAN/airportd), without touching the
system volume: the kexts go through OC `Kernel→Add` and the system IOSkywalkFamily is excluded by
OC `Kernel→Block`.

Load order (`ref_simplebcm/README.en.md:41`): **Lilu → SimpleBCM → IOSkywalkFamily →
IO80211FamilyLegacy → AirPortBrcmNIC** (from the chosen system). The config fragment is
generated by `ref_simplebcm/Tools/configure.py:57-66`, and the block entry is:

```
{ Identifier: "com.apple.iokit.IOSkywalkFamily", Strategy: "Exclude", MinKernel 24.0.0, MaxKernel 25.99.99 }
```
(`ref_simplebcm/Tools/configure.py:64-66`; the comment says "Allow injected IOSkywalk").

The v1.2.0/v1.0.0 numbers are OCLP package versions, not Apple `CFBundleVersion`s; the

`NOTICE.md:14-15` states it: OCLP supplies the files, and the Apple components keep

These Apple kexts are the *IO80211Family "legacy"* of modern Intels: the one living in
`/System/Library/Extensions/IO80211FamilyLegacy.kext` with an `IO80211Controller` of 5-arg ioctl
(`apple80211_ioctl_get(IO80211Interface*, IO80211VirtualInterface*, IO80211SkywalkInterface*, void*)`,
`ref_simplebcm/Docs/ABI.json`, Legacy guards). It already links against IOSkywalkFamily classes,
but with the layout of the era in which Apple compiled it `?`.

## 3. Why the system's IOSkywalkFamily has to be blocked

The injected kext declares the same bundle id `com.apple.iokit.IOSkywalkFamily`; two kexts with the
same identifier cannot coexist, and OC `Block → Exclude` withdraws the system one (exact
mechanics of Exclude over a KC fileset not covered by the repository `?`). The underlying reason
is C++ ABI: `IO80211FamilyLegacy` and `AirPortBrcmNIC` are compiled against the ivars/vtables
of the IOSkywalkFamily of their era; linking them against the Tahoe IOSkywalkFamily would corrupt
the objects (same symbols `__ZN22IOSkywalkInterface…`, different layouts). It is the same
phenomenon measured here between 23/24 and 25: Skywalk classes grow +0x10 and relocate fields
(`Docs/AIRLAYER_PORT_14_15.md:81-87`).

The rest of the modern family (`IO80211Family` inside `BootKernelExtensions.kc`) is **not**
blocked; in a SimpleBCM boot it keeps linking against the injected Skywalk, with old layouts under
Tahoe code `?`. It breaks nothing there because no driver instantiates those classes in a
hackintosh without Apple Broadcom; the point matters for question 3.1 of this document.

## 4. What SimpleBCM.kext patches with Lilu

`Bridge::initialize` chooses the ABI by kernel version and registers load callbacks for three
kexts (`ref_simplebcm/SimpleBCM/Bridge.cpp:635-653`; `KextInfo` table with disk paths at
`:91-101`). The callback `Bridge::patchKext` (`:564-633`) does three things per kext:

1. **Byte validation before touching anything**: each image is cross-checked with `ByteGuard`
   (offset + 32 bytes + mask) at `ref_simplebcm/SimpleBCM/Profiles.hpp`. 72 guards for
   `IO80211FamilyLegacy` (`:19-92`), 1 for `IOSkywalkFamily` (`:110-112`), 10 for each
   `AirPortBrcmNIC` with Sequoia (`:114-125`) and Tahoe (`:131-142`) variants. If it fails:
   `reject("…BinaryMismatch")` and the bridge disarms (`:568-571, :599-602, :618-620`).
   The `PatchState` published in the IORegistry is the OR of bits 1/2/4 per patched kext; 7 =
   ready
   (`:597, :611, :627, :655-657`).
2. **Resolution by full demangled symbol, never fixed offsets**: the pointers the
   bridge needs come from `patcher.solveSymbol` (`:572-579`):
   - `IO80211Controller::apple80211_ioctl_get/set` (5 args),
   - `IO80211Interface::getController`, `IO80211VirtualInterface::getController`,
   - `IO80211Interface::getBSDName`, `IO80211VirtualInterface::getBSDName`,
     `IO80211SkywalkInterface::getBSDName`,
   - `IO80211Interface::performCommand(IONetworkController*, unsigned long, void*, void*)`.
3. **Routes (detours) with `routeMultipleLong`** (`:585-591`):
   - `IO80211Interface::newUserClient` and `IO80211VirtualInterface::newUserClient` →
     `newClassicClient`/`newVirtualClient` (`:206-218`): if `type==0` and the bridge is ready,
     they substitute the family user client with their own.
   - `IO80211Interface::IO80211InterfacePostMessage`,
     `IO80211VirtualInterface::IO80211InterfacePostMessage` and
     `IO80211InfraInterface::postMessageInternal` → `postClassic`/`postVirtual`/`postInfra`
     (`:438-451`): they copy every event into its own queue before calling the original.
   - In the injected Skywalk, only
     `IOSkywalkEthernetInterface::newUserClient` → `newSkywalkClient`, which additionally requires
     `metaCast("IO80211SkywalkInterface")` (`:220-225, :598-611`).

Additionally, **rewriting of the `call`s to `_copyin`/`_copyout`** inside the legacy family and the
driver (`patchCopies`, `:532-562`; `CopySite` table, `Profiles.hpp:93-108,126-129,143-146`;
14 sites in Legacy, 2 in each AirPort). It verifies that the real destination after following
`E9`/`jmp [rip]` up to 3 jumps (`followBranch`, `:515-530`) matches the kernel symbol
`_copyin`/`_copyout` resolved by name, and rewrites the displacement to point to
`bridgeCopyIn`/`bridgeCopyOut` (`:143-155`). With that, every user memory access the family makes
while the bridge has a command in flight is redirected to a kernel "shadow": `Bridge::command`
points
`request.data` at the shadow buffer and registers the range per thread (`CopyContext`,
`:453-482`), so
the family handlers that do `copyin/copyout` over the payload read/write the translated buffer
without knowing it. The list of adapted sites, with the symbol of each, is in
`ref_simplebcm/Docs/ABI.json`/`Docs/Control-Codecs.json` (`adaptedCopySites`): among others,
`getAwdlCtl`/`setAwdlCtl` (input and output copy), `setDebugInfo`, `setRangingEnable`,
`setRangingStart`, `setRangingIdentifier`, `getRangingResults`, `getRangingCapabilities`, and the
generic `IO80211Controller::copyIn/copyOut`.

The two AirPort sites are `AirPort_BrcmNIC::wlIocCommon(apple80211req*, OSObject*, bool, bool)`
(`Control-Codecs.json`, images AirPort/AirPortSequoia: `+0x70` copyin, `+0x1fe` copyout).

## 5. The project's own user client and the struct translation

`IO80211APIUserClient` (`ref_simplebcm/SimpleBCM/UserClient.cpp:13-64` in the header,
implementation `UserClient.cpp`) re-implements the Apple user client contract for the
native Sequoia/Tahoe clients (CoreWLAN/airportd/CoreWiFi):

- It requires the entitlement `com.apple.wlan.authentication` (`UserClient.cpp:37`); and
  `com.apple.private.wifi.IO80211.get_pmk` for request 0x178/376 (PMK, `:301`).
- Selectors 0-8: `Command`, `UseIOUC`, `Subscribe`, `MonitorStart`, `MonitorStop`,
  `UseEventPipe`, `LargeCommand`, `DriverKitSupported`, `MapUserBuffer`
  (`WirelessABI.hpp:86-97`). `Command`/`LargeCommand` carry the packet
  `CommandHeader(8) + buffer(0x3C00 / 0x3C000) + Request(0x28)`
  (`WirelessABI.hpp:17-22,114-117,365-369`; dispatch at `UserClient.cpp:165-168,243-400`).
  The ioctl constants are `GetCommand 0xC02869C9` and `SetCommand 0x802869C8`
  (`WirelessABI.hpp:17-18`).
- Monitoring via shared ring: `EventRing` with a 0x30 `EventHeader`
  (`WirelessABI.hpp:300-310,318-363`), memory `kIOMemoryKernelUserShared`
  (`UserClient.cpp:402-434`), notification via `sendAsyncResult64` with
  `EventNotification 0xE00002D5` (`WirelessABI.hpp:23`; `UserClient.cpp:489-493`).
- Event filter bitmap of 0x20 bytes (`WirelessABI.hpp:284-292`), loaded with the request
  `filterMonitorEvents` of the active ABI (0 on Sequoia, 0x234=564 on Tahoe, `:57-61`) `?`
  (number taken from the code; not verified in the 25G241 disassembly).

The active ABI is a five-size table (`WirelessABI.hpp:50-65`):

| Field | Sequoia (24) | Tahoe (25) |
|---|---|---|
| `scanResultSize` | 0x8D8 | 0x8E0 |
| `capabilitySize` | 19 | 21 |
| `associateSize` | 0x384 | 0x38C |
| `joinStatusSize` | 0x1CC | 0x1D4 |
| `filterMonitorEvents` | 0 | 0x234 |

The concrete translations (family "legacy" sizes vs userspace "native" ones) are
documented in `ref_simplebcm/Docs/Control-Codecs.json`:

- Request 12 (CARD_CAPABILITIES): legacy 12 B → native 19/21 B, zero-filling; the
  "scan completion" bit is 0x40 of buffer byte 5 (`ScanCompletionCapabilityByte = 5`,
  `WirelessABI.hpp:36-38`; `expandCapabilities`, `:151-161`). `Control-Codecs.json:562` labels it
  capability 46 (= 5·8 + 6, counting from the buffer start, version included).
- Request 11 (scan result): legacy 1164 B (IE up to 1024) → native 2264/2272 B (IE up to 2048);
  common header 140 B, IE length at 138 (`scanResultTransfer`;
  `prepareScanResult`/`expandScanResult`, `WirelessABI.hpp:129-149`).
- Request 20 (associate): legacy 548 B → native 900/908 B, with a field-by-field table
  (`associateTransfer`; `prepareAssociate`, `WirelessABI.hpp:229-251`).
- Request 216 (roam profiles): legacy bands 124 B vs native 128 B, two bands
  (`roamProfileTransfer`; `runRoamProfiles`, `UserClient.cpp:211-241`).
- Event 9 (join/association done): rebuilds the native state; on Tahoe the state goes at
  +0x1B8/+0x1BC, the result at +0x1C4 and the BSSID at +0x1CC; on Sequoia at +0x08/+0x0C and +0
  (`encodeJoinStatus`, `WirelessABI.hpp:210-227`; read from family handlers at
  `captureJoinEvent`, `Bridge.cpp:273-295`, which re-consults requests 50, 21 and 9).
- Event 0x37 (driver available): legacy 0xB8 B → native 0xF8 B; availability is synthesized from
  the power state (request 19, `encodePowerAvailability`, `WirelessABI.hpp:188-208`) and
  re-played to late monitors (`copyAvailability`, `Bridge.cpp:423-436`).
- `nativeCaller`: the native caller (`Apple80211RawGet`, image UUID `A7A35846…`) passes
  `&req_val` with length 4 when `req_data` is NULL (`Control-Codecs.json`, `nativeCaller`).

Identification of endpoints the bridge serves: the interface must resolve to a controller
`metaCast("AirPort_BrcmNIC")` and the PCI provider must be vendor 0x14E4 with a device-id in
{0x4331, 0x4353, 0x43BA, 0x43A3, 0x43A0, 0x4357, 0x43B1, 0x43B2} (`Bridge.cpp:157-204`). Everything
else (other drivers, other controllers) goes through the originals.

## 6. How `awdl0` comes up

The plugin contains no AWDL code: it creates no interfaces, no peer managers talk. `awdl0` comes
out of the Apple set intact: `AirPortBrcmNIC` declares the card capabilities and the
`IO80211FamilyLegacy` contains the virtual interface path and the peer manager of its era `?`
(binary not inspected). What the repository proves is that the AWDL `ioctls`/events of
Sequoia/Tahoe userspace follow the same path as the rest of apple80211 and that the bridge lets
them through translated:

- The `getAwdlCtl`/`setAwdlCtl` of the legacy family have adapted `copyin`/`copyout` sites
  (`Control-Codecs.json`, `adaptedCopySites`; request numbers not recorded in the repo `?`).
- `getVirtualIfRole` (request 96) is among the supported scalar GETs
  (`Profiles.hpp:18`; `Control-Codecs.json`, `scalarGetRequests`).
- The project diagnostics consult `ifconfig awdl0`, `netstat -I awdl0` and logs of `wifip2pd`
  (subsystem `com.apple.awdl`), `sharingd` (AirDrop category) and `mDNSResponder`
  (`ref_simplebcm/Tools/collect.py:34-41`): the stack expects `awdl0` working with the same
  daemons this project already documented.

## 7. Answers for this project

### 7.1 Can `RTL8814AirLayer.kext` coexist in the same boot with SimpleBCM?

**No.** They are alternative boots, not coexistence. Reasons:

1. **IOSkywalkFamily blocking.** In a SimpleBCM boot the only `com.apple.iokit.IOSkywalkFamily`
   is the injected v1.2.0, with C++ layouts of its era. `RTL8814AirLayer` declares a dependency
   `com.apple.iokit.IOSkywalkFamily 1.0` (`Source/AirLayer/Info.plist:60-61`) and its binary is
   compiled against the 25.6.0 sizes/offsets (`build_airlayer.sh:5,25-26`; headers
   `Source/IO80211/IO80211_25_6_0.h`). Loading it against the old Skywalk would give wrong ivar
   shifts and vtable slots: exactly the corruption type `Docs/AIRLAYER_PORT_14_15.md:81-87`
   measures between versions (+0x10 per class on 25). Symbol resolution would not protect: the
   `__ZN22IOSkywalk*` names exist in both eras.
2. **The modern family of the KC breaks along the way.** `IO80211Family` (in
   `BootKernelExtensions.kc`)
   also links IOSkywalkFamily; with the fileset excluded and replaced, its classes come to rest on
   old layouts `?`. Today there is no problem because nobody instantiates those classes in that
   boot;
   `RTL8814AirLayer` would be the first.
3. **Namespace clashes.** `IO80211FamilyLegacy` defines classes with the same names
   as the KC family (`IO80211Controller`, `IO80211Interface`…) under a different bundle id
   (`com.apple.iokit.IO80211FamilyLegacy`); that both coexist is precisely the SimpleBCM
   configuration and it works through by-dependency resolution `?` (there is no dump of that
   boot). But
   `RTLAirController : IO80211Controller` (modern) and `AirPort_BrcmNIC : IO80211Controller`
   (legacy)
   would be two parallel hierarchies with homonymous metaclasses; OSMetaClass registers by global
   name `?`. Additional risk, not blocking by itself.
4. **What would coexist**: `RTL8814Native.kext` only depends on
   IONetworkingFamily/IOUSBHostFamily
   and KPIs (`Source/Driver/Info.plist:302-316`): it loads the same in a SimpleBCM boot. The
   SimpleBCM hooks do not affect it (its `identify` requires `AirPort_BrcmNIC` and PCI 0x14E4,
   `Bridge.cpp:181-198`). But without AirLayer there is no `awdl0`, and SimpleBCM provides no
   AWDL for a non-Broadcom adapter.
5. **The ioctl contracts match, they do not clash.** `SetCommand 0x802869C8` / `GetCommand
   0xC02869C9`
   (`WirelessABI.hpp:17-18`) is the pair this project already identified as the token of the
   internal 0x802869C8 with the type in the high dword (`AWDL_PEERMANAGER_SOFTWARE.md`). If
   someday a SimpleBCM-style bridge were wanted for the RTL layer, userspace would speak with the
   same constants.

### 7.2 Reusable techniques to support macOS 14 and 15 with the project's own layer

- **Per-Darwin ABI table with a single binary** (`userABIForKernel`, `WirelessABI.hpp:63-65`;
  `PluginConfiguration` with `KernelVersion::Sequoia..Tahoe`, `SimpleBCM.cpp:72-82`): the same
  pattern as the per-build gate planned here (KnownBuilds/VersionGate). Applicable to the
  apple80211 payload sizes the layer processes, which change per version (the five sizes of §5
  are an independent measure of those changes).
- **Byte validation at load time, not offline** (`validate` + `ByteGuard` with mask,
  `Bridge.cpp:484-513`): the idea matches the guards of
  `Docs/AWDL_VERSION_SENSITIVE_OFFSETS.md`
  (verified byte patterns), but executed in `patchKext` before trusting an offset.
  For the RTL layer, the analogue is validating at `start` time the 25.6.0 bytes the
  vtable/cell offsets rest on before installing hooks, and disarming (like `reject()`) if the
  kernel is not the expected one.
- **Resolution by full symbol with destination verification** (`solveSymbol` +
  `followBranch`): exactly the already adopted rule of "resolve by symbol instead of fixed
  offsets" for 14/15; the useful addition is verifying that the resolved symbol falls inside the
  image and that the site to patch is the expected `call`/`E9` (`patchCopies`, `:532-562`).
- **Struct translation by shadow with intercepted `copyin`/`copyout`**: if someday the
  userspace of a version changes the size of a struct the layer processes by reference, it can
  be translated in a shadow buffer without touching every handler; the per-thread
  `CopyContext` mechanism (`:453-482`) is the detail that avoids translating foreign copies.
- **Availability replay and event conversion** (`availability[]`, `copyAvailability`;
  `encodeJoinStatus`): the events 9/0x37 with per-version layouts are directly comparable with
  the family of events stage 1 emits; useful as a cross-reference of native sizes per
  version.
- **What should NOT be copied**: replacing the IOSkywalkFamily. For 14/15 the layer compiles
  against the headers of each version (already done for 25.6.0); the SimpleBCM approach exists
  because its backend is a closed Apple binary of another era, and its price is losing the system
  Skywalk. The native RTL layer has no such constraint.

### 7.3 What it reveals about what AirDrop requires from the Wi-Fi side

- **Nothing new on the AWDL surface**: the same `wifip2pd`/`sharingd`/`mDNSResponder` over
  `awdl0` this project documented (`AWDL_AIRDROP_SIN_BLUETOOTH.md`; `Tools/collect.py:38-40`
  watches exactly those three processes). The Sequoia/Tahoe userspace introduces no new AWDL path
  over Skywalk: the AWDL controls remain apple80211 requests over the interface
  (`getAwdlCtl`/`setAwdlCtl` adapted in the bridge), and virtual interface creation remains the
  family's business (`getVirtualIfRole`, request 96). It reinforces the stage 1 bet:
  answering `VIRTUAL_IF_CREATE` and the events is enough surface.
- **`CARD_CAPABILITIES` is short and versioned**: 21 bytes on Tahoe (19 on Sequoia, 12 in the
  legacy era) per `capabilityTransfer` and `capabilitySize`. The indices the RTL layer already
  writes (byte 8 bit 0x01 AWDL, byte 7 bit 0x01, byte 7 bit 0x20 dual band —
  `HANDOFF_AWDL.md` §3.2 and `AWDL_SECUENCIA_CON_INFRA.md`) fit in that array; buffer byte 5 bit
  0x40 (the layer's `p[5]`) that SimpleBCM turns on to advertise "scan completion events" on
  classic interfaces
  (`expandCapabilities`, `WirelessABI.hpp:151-161`) is one more bit of the same map `?`
  (semantics taken from the code, not verified against Apple).
- **The native client tolerates minimal answers**: `Apple80211RawGet` with `req_data` NULL asks
  for a 4-byte output (`nativeCaller`), and the user client encodes the scalar GETs as a `value`
  of 4 bytes copied to the buffer (`encodeScalarResult`, `WirelessABI.hpp:119-127`; list
  `ScalarGetRequests`, `Profiles.hpp:18`). The layer stubs that return scalars must
  write those 4 bytes in `req.value`, not in `req.data`.
- **Availability is announced with event 0x37 and re-played**: the "driver available" state
  derives from the power state (request 19) with reason `0xE0821803`
  (`encodePowerAvailability`, `WirelessABI.hpp:188-208,34`) — the same constant the layer already
  saw as "unavailable" in getters (`Docs/PHASE5_IO80211.md`, getRATE). For a client to see the
  adapter "ready" even when the monitor starts late, the last availability event per interface
  must be retained (`availability[]`/`copyAvailability`, `Bridge.cpp:61-66,423-436`).
- **PMK protected**: request 0x178/376 requires its own entitlement
  (`com.apple.private.wifi.IO80211.get_pmk`, `UserClient.cpp:301`); the RTL layer must not answer
  that request without an equivalent filter if it ever exposes it.
